# Axis 6: ADR-015 pseudonym handling for remote actors

## What this catches

New handlers or DB-write helpers that pass a non-`None` value to `actor_pseudonym` for
a remote actor. ADR-015 mandates: local actors get a pseudonymised `actor_pseudonym`
(assigned at registration time); remote actors get `None` — pseudonymisation is only
possible for local users under direct operator control. Passing a non-`None` value for
a remote actor violates GDPR pseudonymisation contract and is a data-integrity error.

## Trace Up ↑

Invariant defined in: ADR-015 (`actor_pseudonym` for local actors; `None` for remote)
in `docs/brehon-law-inspired-network/99-decisions-and-open-questions.md`

Source lesson: `.claude/lessons/feedback_multi_write_handlers_need_transactions.md`
(callsite pattern for DB-write helpers; `actor_pseudonym` is passed as a field in the
struct initializer when calling governance_log or related DB helpers)

Phase-6 instance: Held — all existing Phase-6 governance handlers correctly pass `None`
for `actor_pseudonym` when recording actions taken by remote actors. No violation was
observed in `v1-federation-inbound-a` or `-b`.

## Trace Down ↓

Detection command(s):

1. Grep target file for all `actor_pseudonym` call sites:
   `grep -n "actor_pseudonym" <target_file>`

2. For each call site, determine if the surrounding context is processing a REMOTE actor:
   - Remote-actor markers: `ApubObject::from_apub`, `inbox.rs` receive handlers,
     `RemoteModerationLabel`, `RemoteSanctionNotice`, `RemoteTrustAttestation` types.
   `grep -nB 10 "actor_pseudonym" <target_file> | grep -E "Remote|apub|from_apub|actor_id"`

3. For each remote-actor call site, check the value passed to `actor_pseudonym`:
   `grep -nA 3 "actor_pseudonym" <target_file>`
   Expected: `actor_pseudonym: None`
   Flag: any non-`None` value (e.g. a computed pseudonym, a forwarded field, or a
   `.unwrap_or(None)` expression that could resolve to a non-`None` value).

4. Compare against in-file sibling call sites for the same pattern:
   `grep -nB 2 -A 2 "actor_pseudonym: None" <target_file>`

## Evidence string format (cap 120 chars)

`axis-6: <file>:<line> new=<value-passed> remote_actor=<bool> expected=None`

Example:
`axis-6: inbox.rs:750 new=Some(pseudonym) remote_actor=true expected=None`
