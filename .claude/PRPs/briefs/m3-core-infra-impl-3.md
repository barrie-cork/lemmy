## §4 Constraints

### ADR-015 load-bearing (§2.4a — mandatory, not deferrable)

**Gate: `mint_access_token`'s `identity` / `sub` is a pseudonym — never `person_id`, username, or email.**

- **Specific gate:** fn signature is `mint_access_token(api_key: &str, api_secret: &str, room: &str, identity: &str, ttl_secs: u64) -> anyhow::Result<String>` — `identity` is the opaque pseudonym string. There is NO variant that accepts a `PersonId`, numeric id, or any user-identifying field.
- **Why it cannot be deferred:** a real identity in the LiveKit `sub` reaches the LiveKit server log and breaks the `always_pseudonym` anonymity guarantee — the load-bearing ADR-015 seam for the entire M3 cluster. Once a real identity leaks into a server log, it cannot be retracted.
- **DoD line (required):** `grep 'sub:' services/bridge/src/livekit_jwt.rs` returns `sub: identity` (the pseudonym param) AND `grep -i 'person_id\|username\|email' services/bridge/src/livekit_jwt.rs` returns nothing.

### Implementation constraints

1. **`livekit_jwt.rs` Claims struct:** `iss: api_key`, `sub: identity`, `nbf: now_unix`, `exp: now_unix + ttl_secs`, `video: VideoGrant { room, room_join: true }`. Sign HS256 via `jsonwebtoken::encode(&Header::new(Algorithm::HS256), &claims, &EncodingKey::from_secret(api_secret.as_bytes()))`. Derive with `serde::Serialize` + `serde::Deserialize`.

2. **`#[cfg(test)]` unit test in `livekit_jwt.rs`:** mint with a sample pseudonym string (not a real person id — use e.g. `"pseu_abc123"`) → decode (skip validation or use same secret) → assert `sub == "pseu_abc123"`, `iss == api_key`, `video.room == room`, `exp > nbf`.

3. **`config.rs` optional fields:** add 3 fields per §10.6 — read with `.ok()` (not `.context()?`), so a governance-only bridge starts without LiveKit creds:
   ```rust
   /// Optional LiveKit server URL (e.g. "wss://livekit.example.com"). Required only when RTC is enabled.
   pub livekit_url: Option<String>,
   /// Optional LiveKit API key. Required only when RTC is enabled.
   pub livekit_api_key: Option<String>,
   /// Optional LiveKit API secret. Required only when RTC is enabled.
   pub livekit_api_secret: Option<String>,
   ```
   In `from_env()`: `livekit_url: env::var("LIVEKIT_URL").ok()`, etc.

4. **`main.rs` mod:** add `mod livekit_jwt;` after `mod link_handler;` (alphabetical — `livekit_jwt` < `provision`).

5. **`Cargo.toml` dep:** add `jsonwebtoken = "9"` under `[dependencies]`. Do NOT pin to a sub-minor — `"9"` resolves the latest compatible `9.x`. Regenerate `Cargo.lock` by running `cargo-linux.sh check` (see VALIDATE below); commit the updated lock file.

6. **Clean-posture:** a bridge that starts with no LiveKit env vars must not panic. The optional fields return `None`; `mint_access_token` is only called at runtime when creds are supplied.
