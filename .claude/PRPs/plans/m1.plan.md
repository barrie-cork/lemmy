## 1. Summary

M1 ships the **chat infrastructure** plane for Brehon: a Matrix homeserver (Tuwunel) plus a greenfield, workspace-EXCLUDED Rust application-service bridge daemon at `services/bridge/`, wired to the Brehon binary through the existing 7 PM plugin hooks (read-only notify, no new hooks). It delivers 1:1 direct messages with rich media (text / image / voice note), an admin config panel backed by a new `governance_messaging_config` table, an ADR-015 identity-policy validator that structurally rejects jury/appeals overrides from day one, and a clean-disable / soft-pause posture. **Headline acceptance:** with `messaging_enabled = false` the v0 governance-only posture is byte-for-byte unchanged; with it enabled, a 1:1 DM (text + image + voice) round-trips Brehon↔Matrix in < 3s, and the whole surface is reversible (enable→disable→enable) without a process restart. The bridge is its own crate tree — `cargo build --workspace` pulls **zero** Matrix dependencies.

## 3. Problem statement

Brehon v0/v1 has no real-time chat plane. The umbrella V2 PRD calls for messaging, town halls, and RTC; M1 is the first slice — chat infrastructure only. Before M1:

- There is no Matrix homeserver and no bridge (`services/bridge/` ABSENT — §0 brief). → Tree A, Tasks 8–13.
- There is no per-instance messaging config; `messaging_enabled`, identity-policy default, and lifecycle policy have nowhere to live (`governance_messaging_config` table ABSENT). → Task 1–5.
- The PM plugin hooks fire but nothing downstream consumes them for chat (`plugins.rs:33/48/103`, `notify.rs:305`). → Task 6.
- ADR-015 forbids jury/appeals identity-policy overrides, but nothing enforces it; if the admin panel ships without a validator, an operator could set a non-pseudonymous default for a room class that M2 will introduce. → Task 5.
- The standard Brehon DoD (`cargo check --workspace`) cannot cover a workspace-excluded daemon, so M1 must define a second, bridge-local validation path. → §15.2.

## 4. Solution statement

Two ownership trees plus an ops/docs tree:

```
                     Brehon binary (lemmy_server, in-workspace)
                     ┌───────────────────────────────────────────┐
   admin HTTP  ───▶  │  api/routes → governance/messaging_config   │
                     │  (admin_set_messaging_config, single write) │
                     │            │                                │
                     │            ▼                                │
                     │  governance_messaging_config (NEW table)    │
                     │  messaging_enabled / identity_policy /      │
                     │  hard_delete_after_days  (typed cols)       │
                     │            │ identity-policy validator      │
                     │            │ (ADR-015 pin)                   │
                     │  PM send ──┤ plugin_hook_notification        │
                     │            ▼ (existing seam, notify.rs:305)  │
                     │      bridge_notify.rs (read-only, fire if    │
                     │      messaging_enabled)                      │
                     └────────────┼────────────────────────────────┘
                                  │  HTTP notify (localhost)
                                  ▼
   ┌──────────────────────────────────────────────────────────────┐
   │  services/bridge/  (Tree A — greenfield, workspace-EXCLUDED)  │
   │  axum AS-transaction server  ◀── Tuwunel /transactions        │
   │  appservice.rs · puppet.rs · relay.rs · provision.rs ·        │
   │  soft_pause.rs                                                 │
   │  matrix-sdk 0.18 (client/puppet/media) + ruma-appservice-api  │
   │  bridge-local messaging_user_id puppet map (NOT B-actor)      │
   └──────────────────────────────┬───────────────────────────────┘
                                  │ Matrix C-S + AS API
                                  ▼
                       Tuwunel homeserver (docker-compose)
                       federation disabled launch posture
```

Tree B is additive Brehon-side: one migration + Diesel model + DTOs + a single-write admin handler (mirrors `admin_config.rs` but **drops** the `governance_log::append` → single write → no `run_transaction`) + the identity-policy validator + a read-only `bridge_notify` wired into the existing PM notification path. Tree C wires Tuwunel + bridge in docker-compose and updates the chat-plane design docs.

## 10. Patterns to mirror

### 10.1 Typed-column config table (migration)

**Mirror:** `migrations/2026-04-18-000000-0000_add_governance_config/up.sql`

```sql
CREATE TABLE governance_messaging_config (
    id          SERIAL PRIMARY KEY,
    scope       TEXT NOT NULL,         -- 'instance' | 'community:<id>' | room-type
    key         TEXT NOT NULL,         -- 'messaging_enabled' | 'identity_policy' | 'hard_delete_after_days'
    value_type  TEXT NOT NULL,         -- 'int' | 'bool' | 'text'
    value_int   BIGINT,
    value_bool  BOOLEAN,
    value_text  TEXT,
    valid_from  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by  INTEGER REFERENCES person (id) ON DELETE RESTRICT,
    CONSTRAINT governance_messaging_config_typed CHECK (
        (value_type = 'int'  AND value_int  IS NOT NULL AND value_bool IS NULL AND value_text IS NULL) OR
        (value_type = 'bool' AND value_bool IS NOT NULL AND value_int  IS NULL AND value_text IS NULL) OR
        (value_type = 'text' AND value_text IS NOT NULL AND value_int  IS NULL AND value_bool IS NULL)
    )
);
CREATE UNIQUE INDEX governance_messaging_config_scope_key_valid_from_idx
    ON governance_messaging_config (scope, key, valid_from);   -- append-history; NOT (scope,key) — GOTCHA-50a
CREATE INDEX governance_messaging_config_scope_key_idx
    ON governance_messaging_config (scope, key);
CREATE VIEW governance_messaging_config_current AS
SELECT DISTINCT ON (scope, key)
    id, scope, key, value_type, value_int, value_bool, value_text, valid_from, updated_by
FROM governance_messaging_config
ORDER BY scope, key, valid_from DESC;
-- Seed: messaging_enabled=false (bool), identity_policy='pseudonymous' (text, instance default), with literal valid_from + ON CONFLICT DO NOTHING.
```

> No `value_float` column (M1 has no float-typed messaging config — int/bool/text suffices). If a float key ever appears, add the column + CHECK arm in a fresh migration (never mutate this CHECK in place).

### 10.4 Identity-policy validator (ADR-015 structural pin)

**Mirror:** the validation-rejection shape in `admin_config.rs` `check_policy` denial path (`:426`, returns a typed `LemmyError`).

```rust
// Rejects any attempt to set a jury/appeals room-type identity_policy to a non-pseudonymous value.
// Vacuously satisfied in M1 (jury/appeals rooms arrive in M2) — the gate exists NOW so M2 cannot
// introduce a non-pseudonymous default. ADR-015.
fn validate_identity_policy(data: &AdminSetMessagingConfig) -> LemmyResult<()> {
  if data.key == "identity_policy"
    && matches!(data.scope.as_str(), s if s.starts_with("jury") || s.starts_with("appeal"))
    && data.value.as_str() != Some("pseudonymous")
  {
    return Err(LemmyErrorType::/* CouldnotUpdate-style */.into());  // structural refusal
  }
  Ok(())
}
```

### 10.5 Read-only bridge notify (existing seam, fire-if-enabled)

**Mirror:** `crates/api/api_utils/src/notify.rs:305` (the `plugin_hook_notification` PM-notify call) + `plugins.rs:48` (`plugin_hook_notification` signature).

```rust
// Called alongside the existing plugin_hook_notification at notify.rs:305 — does NOT replace it,
// does NOT add a new hook. Reads messaging_enabled; if false, no-op (clean posture). If true,
// fire-and-forget HTTP POST to the bridge. NEVER blocks the PM path.
pub async fn notify_if_enabled(context: &LemmyContext, notification: &PrivateMessageView) -> LemmyResult<()> {
  if !read_messaging_enabled(&mut context.pool()).await? { return Ok(()); }  // governance_messaging_config_current
  // fire-and-forget POST localhost:<bridge_port>/brehon/notify; log+swallow transport error (NOT a PM-path failure)
  Ok(())
}
```
